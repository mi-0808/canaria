# 新機能の設計チェック

[CLAUDE.md](../../../CLAUDE.md) の「実装ルール」を、実装の各段階で機械的に確認する。
各項目には MyHood β で実際に起きた失敗が紐づいている。根拠が当てはまらない場面では曲げてよいが、曲げた理由をコメントに残す。

## 実装前

- [ ] プランを出して承認を得たか（変更ファイル・影響範囲・懸念と代替案）
- [ ] UI を作るなら、参考画像・参考サイトがあるか。**無ければ作り始める前に聞く**
- [ ] 「将来使うかも」で作っていないか。依存を足そうとしていないか

## 設計

### データ取得（該当する場合）

- [ ] 独立した `await` を直列に並べていないか → `Promise.all`
- [ ] 画面全体の描画を fetch 完了でゲートしていないか（待つのは骨格を決める最初の1件だけ）
- [ ] 一覧クエリに `order` + `limit` が付いているか
- [ ] 一覧のカードが個別にリアルタイム購読を張っていないか
- [ ] `useEffect` の deps が primitive（`user?.id`）か

### データと権限（該当する場合）

- [ ] **新しいテーブル・バケットの RLS を同じ PR で `supabase/schema.sql` に書いたか**
- [ ] 書き込みを `using (true)` で許可していないか
- [ ] 新旧のデータ形式を併存させていないか
- [ ] データが無いときにモックを返していないか

### ファイルサイズ

- [ ] 500行を超えたファイルを触っているなら、このタイミングで割る

## 実装後

- [ ] `npm run check` が通るか
- [ ] 非自明なロジック（分岐・ループ・パース・認可）に**実行できるチェックを1つ残したか**（`assert` 1本で十分）
- [ ] UI を触ったなら `/ui-check` を走らせたか
- [ ] カメラ・ファイル選択・音声・動画に触ったなら、PC では再現しない旨を明示して実機確認を依頼したか
- [ ] 検証できていないことを「できた」と言っていないか
- [ ] 意図的に省いたものと、それを足すべき条件を1行で添えたか
