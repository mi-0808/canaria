# UI チェック

UI を触ったら離れる前にこれを通す。根拠は [src/app/design.css](../../../src/app/design.css) 冒頭のルール。

## 1. トークン

- [ ] 色を design.css のトークン（`bg-surface` / `text-fg-2` / `bg-primary` など）から取っているか
- [ ] 任意の値（`text-[13px]`、`#fff`、`rgba(...)`）を直接書いていないか
- [ ] 足りないトークンを使いたい場合、**先に design.css にトークンを足して**から使ったか
- [ ] 面の色と文字色をペアで使っているか（`bg-primary` なら `text-on-primary`）
- [ ] 濃いカナリアの塗り（`bg-primary` / `btn-primary`）が1画面に1つか
- [ ] グラデーション・発光する影を使っていないか

### Tailwind 標準色の罠

Tailwind 標準色は無効にしてあるので、`bg-zinc-100` などは**ビルドが通るのに色が付かない**。`npm run check` が `scripts/check-tokens.sh` で落とす。
トークン名の打ち間違い（`bg-primery`）は検査で拾えないので、画面で色が付いているかを見る。

## 2. アクセシビリティ（WCAG 2.1 AA）

後付けしない。触った画面は基準に寄せてから離れる。

- [ ] 本文16px / 補助14px を下回っていないか。`text-xs` はバッジ・時刻・注記だけか
- [ ] 押せる要素が 44px 以上あるか
- [ ] `focus-visible` の表示を消していないか
- [ ] 情報を色だけで伝えていないか
- [ ] 画像に `alt` があるか（装飾は `alt=""`）。アイコンだけのボタンに `aria-label` があるか
- [ ] 押せるものが `<button>` / `<a>` か

## 3. 実際に見る

- [ ] プレビュー（`.claude/launch.json` の `dev`）で開いたか
- [ ] **375px 幅で横スクロールが出ないか**（`document.documentElement.scrollWidth > innerWidth` で確かめる）
- [ ] スマホの値を先に書き、`sm:` / `md:` で広げる順になっているか。固定幅を使っていないか
- [ ] ホバーでしか出ない操作・情報が無いか
- [ ] ナビゲーションが 375px に収まっているか
- [ ] 375px と 1280px の2幅でスクリーンショットを撮ったか
- [ ] 空状態・エラー状態・読み込み中の状態があるか（無いなら、要るかどうかを1行で報告する）

ブラウザ操作ができない環境なら、それを明示して人に確認を依頼する。**見ていないものを「確認した」と書かない。**

## 4. 時間を空けたレビュー

実装直後のレビューは「動いた」で満足してしまう。**別の日に**スクリーンショットを見てもらう。今できるのは撮って渡すところまで。
